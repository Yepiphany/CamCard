# 本地数据模型

以下为逻辑模型。应用使用 Codable 持久化名片及分组，测试可以使用同一仓库的内存模式。标识符在创建时分配，编辑时保留原标识。图像文件以应用目录下的相对路径引用。

| 实体 | 字段与关系 |
| --- | --- |
| BusinessCard | ID、原图引用、校正图引用、已确认字段、普通备注列表、创建与更新时间、最近查看时间及可选通讯录标识。关联一个识别记录，可关联分组。 |
| ContactFields | 姓名、公司、职位、部门、第二组公司及职位、网站和地址可空。手机、办公电话、邮箱和传真为有序列表。可选姓名详情保存姓、名、拼音、前后缀、中间名和昵称。 |
| RecognitionRecord | 关联名片 ID，保存识别语言、原始文字、识别区域、结构化候选和识别时间。人工修改写入已确认字段。 |
| Group | ID、显示名、创建时间。分组和名片通过关联关系查询，删除分组只删除关系。 |
| ScanDraft | 临时会话 ID、原图、当前四边形与方向、校正图、识别记录及待确认字段。保存成功后转换为持久化记录。 |

单值缺失用空值表示，多值缺失用空列表表示。电话号码保留用户确认的显示文本，搜索用去除排版分隔符的索引值。邮箱搜索忽略大小写。字段可含多个候选时，先由用户确认后再保存。名片删除后，清理关联的独占图像与识别记录。

写入顺序须保证查询不到引用缺失图像的名片。保存先暂存并验证图像，再提交元数据和关联。提交前失败时清理暂存文件，提交后清理失败可在后续启动重试。重复提交同一草稿须复用名片 ID。阶段 2 起为结构变更记录迁移方案，并保留已保存名片的重启回归用例。


第五阶段将 `library.json` 和按名片 ID 命名的 PNG 写入应用的 Application Support 目录。元数据原子替换，删除分组和清除名片分组引用在同一次写入完成。图像先写入，元数据提交成功后才可见。读取到有效元数据后可清理无引用的图像。新增字段为可选值，旧的单条备注在读取时作为普通备注显示。无法解析现有索引时保留原文件并阻止写入。

第六阶段增加的字段均为可选项，旧记录可以直接解码。单一系统通讯录组织字段使用第一组公司与职位，第二组保留在应用中。
