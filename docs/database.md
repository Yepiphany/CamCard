# 本地数据模型

应用使用 Codable 序列化名片和分组。测试可以使用同一仓库的内存模式。名片标识在创建时分配，编辑保留原标识，图像通过相对文件名引用。

| 类型 | 字段与关系 |
| --- | --- |
| `BusinessCard` | UUID、原图与校正图引用、已确认字段、可选识别记录、分组 ID 集合、备注列表、收藏标记、创建时间、更新时间、最近查看时间和可选通讯录标识。 |
| `ContactFields` | 姓名、公司、职位、部门、第二组公司及职位、网站和地址可空。手机、办公电话、邮箱和传真为有序列表。可选姓名详情保存姓、名、拼音、前后缀、中间名和昵称。 |
| `RecognitionRecord` | 直接嵌入名片的可选字段，保存识别语言、原文、文字区域、结构化候选值和识别时间。人工修订写入名片的已确认字段。 |
| `CardGroup` | UUID、名称和创建时间。名片使用分组 ID 集合记录归属。删除分组会清除对应归属。 |
| `CardNote` | UUID、文本、记录日期、可选拜访信息和可选附件列表。拜访信息包含拜访日期、方式、结果及可选回访时间。 |
| `CardNote.Attachment` | UUID、类型和可选经纬度。照片与录音数据单独存储，位置附件直接记录坐标。 |
| `ScanResult` | 扫描会话中的原图、当前图像、边界、校正图、识别记录及手动裁剪状态。待确认字段由 `ScannerView` 单独保存。 |

单值缺失用空值表示，多值缺失用空列表表示。电话保存用户确认的显示文本，匹配时去除排版分隔符。邮箱搜索忽略大小写。通讯录与 VCF 的组织字段使用第一组公司和职位，第二组保存在名片中。

应用将 `library.json`、按名片 ID 命名的 PNG 和按附件 UUID 命名的 `note-asset-<UUID>` 写入沙盒的 Application Support 下的 `CamCard` 目录。带图名片和备注附件在保存时先写文件，再原子替换索引。索引写入失败时清理此次写入的文件。删除名片或附件时先更新索引，再清理关联文件。成功读取索引时也会清理无引用的图像和附件。索引无法读取或解码时，仓库保留原文件并阻止写入。

收藏、拜访信息和附件等新增字段使用可选值。旧版单条文本备注在读取时作为普通备注显示，下次保存备注列表时转为当前结构。 [数据类型](../CamCard/BusinessCard.swift) · [本地仓库](../CamCard/CardRepository.swift)
