# 移动应用开发课程报告：名片数字化与联系人管理

项目以 iOS「名片全能王」为黑盒参考，复刻从采集名片到导出联系人的业务闭环。开发采用 SDD：先记录可观察行为和验收条件，再实现、测试和修订。参考 App 通过 iPhone 镜像观察；本项目在 Xcode 的 iPhone 18 Pro 模拟器（iOS 27.2）运行。项目以六个阶段组织工作。

## 范围与实现

| 模块 | 实现 |
| --- | --- |
| 采集与校正 | 实时相机预览、快门、补光、相册导入、旋转、边界检测、透视校正及手动角点调整。相册导入用于模拟器验收。 |
| 识别与校对 | Apple Vision 在设备端执行文字识别，保留原文及文字区域。规则提取结构化字段，未确认字段留空。用户可修改或清空字段，确认后保存。 |
| 管理 | 名片夹、详情、编辑、删除、搜索、分组、普通备注及拜访日志；本地重启后可重新查看。 |
| 导出 | 存入系统通讯录及生成 VCF。电话、邮件和网站可交由相应系统应用处理。 |

商业登录、订阅、数字名片在线交换、团队及公开人脉服务不在本次切片内。详细边界见[需求](requirements.md)和[黑盒规格](spec.md)。

## 架构与数据

SwiftUI 负责界面与状态流转。相机采集、图像校正、文字识别、字段提取和仓库分开。仓库使用应用沙盒中的 JSON 索引及独立文件保存名片图像、备注附件和其他元数据。识别候选值和人工确认字段各自保存，便于追溯错误；重识别时，未改动的字段可更新，人工填写或清空的姓名细项持续保留。详见[架构](architecture.md)、[数据模型](database.md)和[内部接口](api.md)。

## 识别评估

项目自建 31 张合成测试图片，覆盖中英文、倾斜、反光、模糊、遮挡、多值、缺失字段及非名片图片。29 张参与字段计分，完整名单及标准答案见[合成测试集](../tests/fixtures/business-cards/README.md)。

| 指标 | 结果 |
| --- | --- |
| 存在字段准确率 | 94/97（96.9%） |
| 缺失字段误填率 | 0/135（0%） |
| 未命中 | CC-016 的公司原文存在字符识别差异；CC-025、CC-026 的公司未被规则提取。 |

对无标签且无法确定类别的号码保持空值，避免将其误分类为手机或办公电话。原文、字段候选值及逐样本差异见 [OCR 日志](evidence/stage-6/ocr.log)。上述结果来自项目合成集。课程文件提到教师固定集；若另行提供，应按相同方法复测。原版尚未使用同一套合成图完成跑分，不能由此推断两者识别准确率相同。

## 验收与差异

[第六阶段验收](stage-6-acceptance.md)按 T01–T20 记录测试与证据。iPhone 18 Pro 模拟器完整 UI 套件 12 项通过，最后的布局和跳转调整也完成了定向复测。补查通过 iPhone 镜像核对扫描四模式、详情、备注列表、拜访日志及回访滚轮。在模拟器用合成图验证导入、识别、裁剪、回归和导出。CC-016、CC-017 手动移动裁剪角点后成功重新识别；损坏数据提示后可以重新导入。电话、邮件、网页的 URL 由测试接收器断言，测试不发起实际外部操作。

参考截图涉及原版已有名片，仓库只保留合成名片和项目截图。系统状态栏、部分原版图标和平台控件外观有差异；原版和项目未完成同图逐像素对照。实际相机权限与画面联动、实时预览、补光和拍摄结果保留未验证状态，不能据此宣称参考用例全部通过。

## AI 协作及验证

- 本项目实际使用 Codex 辅助拆分阶段、维护规格、实现和编写回归用例；原版行为只通过正常操作观察，不读取原版内部实现。
- 先写预期，再修复重识别覆盖姓名细项、扫描模式及备注交互的差异。保存前通过测试验证人工字段不被覆盖。
- 对自动生成的字段和代码都保留检查环节。OCR 概率错误使用固定样本量化，确定性交互用模拟器回归，镜像无法取得的硬件行为单独记录。
- [阶段任务](tasks.md)、[技术决策](decisions.md)和 Git 提交保留开发及修订记录。
