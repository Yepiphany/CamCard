# 应用架构

使用 Swift 和 SwiftUI 构建原生 iOS 应用。采集、识别、保存、搜索及导出均在设备端处理。Apple Vision 执行 OCR，结构化解析由项目实现。图片和名片数据存于应用本地，系统通讯录和 VCF 是两个独立出口。

| 模块 | 职责 |
| --- | --- |
| 名片夹与详情 | 管理导航、搜索、分组、备注和已保存的名片。 |
| 采集 | 管理相机预览、拍摄和照片导入，将图片交给校正流程。 |
| 图像校正 | 保存原图，检测四边形、处理方向及透视，生成裁剪图。 |
| 识别与解析 | OCR 产出文字及位置，字段解析以可追溯的文字为依据。 |
| 草稿编辑 | 保留识别结果与用户确认值，管理取消、重试和保存。 |
| 本地存储 | 保存名片、识别记录、分组、备注及图像引用。 |
| 导出 | 将同一份已确认联系人映射到系统通讯录和 VCF。 |

采集后先校正，再识别和解析，最后进入用户确认。重新裁剪触发识别时，旧任务的异步结果不得覆盖新结果；已手改字段须在重新识别时保留，除非用户明确重置。退出扫描或取消草稿时清理临时资源。保存失败时保留可重试草稿。已保存名片的编辑仅在确认后写入。

通过协议隔离采集、OCR、存储及导出。在模拟器测试中可替换相机和系统权限依赖，用导入照片验证正常识别链路。真实相机画面及实拍按已确认的范围标为未验证。外部电话、邮件和网站跳转通过系统提供的入口触发。

数据字段见[数据模型](database.md)，模块边界见[接口契约](api.md)，验证用例见[验收标准](acceptance-criteria.md)。
